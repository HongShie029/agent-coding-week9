# RETRO — 회고

## 잘된 점
- Mission 4에서 수정해야 할 파일을 `deploy/rollout.js`와 `docs/OPS_DESIGN.md` 3번 섹션으로 한정해 작업 범위를 명확히 했다.
- 정상 배포, 카나리 버전의 오류 급증, 지연 시간 악화, 일시적인 오류 급증, 외부 장애 등 다양한 상황을 구분해 생각했다.
- 카나리와 기존 버전을 비교해야 한다는 핵심 조건과 성급한 롤백을 방지해야 한다는 목표를 정리했다.
- 평가 명령어인 `npm.cmd run eval:rollout`을 통해 결과를 확인하는 검증 절차를 파악했다.

## 아쉬운 점(특히 AI를 믿었다가 틀린 순간)
- AI가 실제 코드와 데이터 구조를 충분히 확인하지 않은 상태에서 `ops` 헬퍼 함수와 메트릭 필드명을 추측해 코드를 제안했다.
- 처음에는 제안된 코드가 실제 프로젝트 구조에 맞는지 확인하지 않고 그대로 활용할 뻔했다.
- 특히 존재 여부가 확인되지 않은 함수와 필드를 사용하면 실행 오류가 발생하거나 평가 조건을 잘못 처리할 수 있다는 점을 알게 됐다.
- 최종 평가 결과를 확인하기 전에 작업이 완료된 것처럼 판단하지 않도록 주의해야 한다.

## 다음 프로젝트에서 바꿀 것 3가지
1. **코드 작성 전 실제 파일 확인하기**  
   계약서, 기존 구현, 데이터 구조를 먼저 확인하고 존재하는 함수와 필드만 사용한다.

2. **AI의 제안을 바로 적용하지 않기**  
   AI가 제시한 코드와 판단 근거를 직접 확인하고, 프로젝트의 요구사항 및 기존 코드와 일치하는지 검토한다.

3. **작은 단위로 수정하고 평가하기**  
   지정된 파일만 수정한 뒤 관련 테스트와 평가 명령어를 실행한다. 통과 결과를 직접 확인한 후 완료로 판단한다.

## AGENTS.md에 실제로 추가 · 수정한 규칙
  - 코드를 수정하기 전에 관련 계약서와 실제 구현 파일을 먼저 확인한다.
  - 확인되지 않은 함수, 필드, 데이터 구조를 추측해서 사용하지 않는다.
  - 사용자가 지정한 파일과 작업 범위를 벗어나 수정하지 않는다.
  - 작업 완료 여부는 평가 명령어 실행 결과를 직접 확인한 뒤 판단한다.
