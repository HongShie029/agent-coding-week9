## 2. 기준선 (AI 산출물, `npm run eval:ai`)
| 영역 | 공개 점수(%) | 가장 눈에 띄는 실패 |
|---|---|---|
| 파이프라인 게이트 | 41% | 테스트 누락, 비밀키 하드코딩, 치명적 취약점 및 위험한 DB 마이그레이션을 차단하지 못함 |

| 알림 규칙 | 71% | 일시적인 오류에도 불필요한 알림이 발생하고, 지연 증가 감지가 기준보다 17분 늦음 |

| MLOps 정책 | 19% | 데이터 이상을 감지하지 못하고 데이터 누수, 성능 하락, 평가 데이터 부족 등의 상황에서도 모델을 승격함 |

| 점진 배포 | 41% | 성능이 저하된 버전을 100% 배포하고 정상 릴리스까지 잘못 롤백함 |

| 런북 완결성(`npm run runbook -- --dir ai_ops`) | 0% | 3개 알림 규칙 모두 runbook 필드가 없어 장애 대응 절차가 없음 |

팀장의 말 "AI 가 만든 운영 자동화가 공개 시나리오를 대부분 통과하니 그대로 써도 되겠다"에 대한 우리 팀의 한 문장 답:
공개 점수는 정해진 시나리오에서의 AI 수행 능력만 보여줄 뿐 실제 운영 환경의 모든 예외 상황과 장애 대응 및 안전성을 보장하지 않으므로, 런북과 안전장치 검증 없이 운영에 적용해서는 안 된다.

## 3. 미션별 작업 단위와 확인 방법
| 미션 | 작업 단위 | 어떻게 확인하나 |
|---|---|---|
| M1 | 파이프라인 게이트 개선: 테스트 누락, 비밀키 노출, 치명적 취약점, 성능 하락 및 위험한 DB 마이그레이션 차단 | npm run eval:ai 실행 후 파이프라인 게이트 점수와 c03, c04, c06, c07, c10 결과 확인 |

| M2 | AI 알림 규칙 개선: 일시적인 오류로 인한 불필요한 알림을 줄이고 지연 증가를 빠르게 감지 | npm run eval:ai 실행 후 A3, A5 결과 확인 |

| M3 | MLOps 정책 개선: 데이터 이상 감지, 재학습 조건 검증, 모델 승격 기준 강화 | npm run eval:ai 실행 후 D1~D4, P1~P8 결과 확인 |

| M4 | 점진 배포 개선: 성능 저하 감지, 카나리 검증, 외부 장애와 배포 장애 구분 및 자동 롤백 기준 개선 | npm run eval:ai 실행 후 R1~R5 결과 확인 |

| M5 | AI 알림 규칙별 런북 작성 및 운영 대응 절차 완성 | npm run runbook -- --dir ai_ops 실행 후 3개 규칙의 런북 완결성 100% 확인 |

## 4. 예상 위험과 안전장치 3가지
1. 위험한 코드와 설정의 자동 반영
2. 잘못된 데이터와 모델 승격으로 인한 AI 품질 저하
3. 장애 감지 실패와 잘못된 자동 대응
