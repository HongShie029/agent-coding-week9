# OPS_REVIEW — AI 가 만든 운영 산출물 리뷰 (Mission 0·5)

## 1. 점검표 (8항목) — `ai_ops/` 4개 파일을 읽으며 해당 사례를 찾는다
| # | 점검 항목 | 의심 사례(파일 · 위치) |
|---|---|---|
| O1 | 고정 임계값 하나로 판단하는가(평소 대비 · 지속성 없음) | ai_ops/alerts.js — 오류율 5%, p95 1,000ms, 오류 50건 등 고정 기준만 사용. ai_ops/policy.js — 분포 변화량 0.03 하나로 드리프트 판단 |

| O2 | 한 분(한 번)의 값으로 호출하는가(일시 급증에 취약) | ai_ops/alerts.js — window[window.length - 1]로 마지막 1분의 값만 확인. ai_ops/rollout.js — 최근 2분만 합산해 오류율 판단 |

| O3 | 전체 평균만 보는가(구간 · 비즈니스 지표 · 결제 실패 · 추천 품질 누락) | ai_ops/alerts.js — 요청 오류와 p95 중심이며 결제 실패율, 추천 CTR, 시간대별 트래픽 및 세부 구간 지표가 없음. ai_ops/policy.js — 카테고리 분포의 평균 위치 변화만 확인 |

| O4 | 게이트가 "테스트 통과"만 보는가(건너뜀 · 커버리지 · 비밀 · 취약점 · 모델 품질 누락) | ai_ops/pipeline.config.js — 테스트 실패 여부와 빌드 실패 여부만 확인. 건너뛴 테스트, 커버리지, 비밀 값, 취약점, 모델 품질 등을 검사하지 않음 |

| O5 | 카나리를 기존 버전과 비교하지 않고 절대값으로만 보는가(외부 장애 오탐 · 작은 회귀 미탐) | ai_ops/rollout.js — 카나리 오류율이 5%를 넘는지만 확인하고 기존 버전인 baseline은 비교하지 않음 |

| O6 | 재학습을 달력으로 하거나 평균 변화만 보는가(데이터 품질과 드리프트를 구분 못함) | ai_ops/policy.js — 14일마다 정기 재학습하고 카테고리 평균 위치 변화만으로 드리프트 판단. 결측·잘못된 가격 데이터와 계절성을 구분하지 못함 |

| O7 | 모델 승격을 "점수가 올랐나"로만 판단하는가(신뢰구간 · 구간별 · 평가 크기 · 누수 무시) | ai_ops/policy.js — 후보 모델의 hitRatePct가 챔피언보다 높으면 바로 승격. 신뢰구간, 평가 데이터 크기, 학습 데이터 누수, 사용자 구간별 성능, 지연 시간을 확인하지 않음 |

| O8 | 알림에 런북 · 담당 · 복구 확인이 없는가 | ai_ops/alerts.js — 규칙에 runbook 연결이 없고 담당자 및 복구 확인 절차도 없음 |

## 2. 결함 표
| ID | 위치 | 유형(O1~O8) | 왜 문제인가 | 어떤 상황에서 터지나(시나리오) | 우리 수정 |
|---|---|---|---|---|---|
| D1 | ai_ops/alerts.js — 오류율·지연·오류 건수 규칙 | O1 | 고정 임계값만 사용해 평소 상태나 SLO와의 관계를 고려하지 못함 | 평소 트래픽이나 지연 수준이 달라지면 오탐 또는 미탐이 발생할 수 있음 | 관찰 창과 SLO, 예상 트래픽을 반영하도록 수정 |

| D2 | ai_ops/alerts.js — window[window.length - 1] | O2 | 마지막 한 분의 값만으로 알림을 발생시켜 순간적인 급증에 취약함 | 일시적인 오류 급증에도 불필요한 알림이 발생할 수 있음 | 지속 시간과 표본 수를 함께 확인하도록 수정 |

| D3 | ai_ops/alerts.js — 전체 지표 판단 | O3 | 결제 실패와 추천 품질 등 비즈니스 지표가 빠져 있음 | HTTP 오류는 없지만 결제 실패율이 증가하거나 추천 클릭률이 하락하는 경우 | 결제 실패율과 추천 품질 알림 규칙 추가 |

| D4 | ai_ops/pipeline.config.js — tests-pass, build-ok | O4 | 테스트와 빌드 성공 여부만 확인해 보안·품질 위험을 놓칠 수 있음 | 비밀 값이나 취약점이 포함되거나 테스트가 건너뛰어진 경우 | 비밀 값, 테스트 누락, 커버리지, 취약점, 모델 품질 등 게이트 추가 |

| D5 | ai_ops/rollout.js — decide() | O5 | 카나리와 기존 버전을 비교하지 않고 절대 오류율만 확인함 | 외부 장애로 두 버전 모두 오류가 증가하거나 카나리만 나빠지는 경우 | 카나리와 baseline의 오류율·지연 시간을 비교하고 지속적인 회귀에만 롤백 |

| D6 | ai_ops/policy.js — retrainDecision(), detectDrift() | O6 | 정기 재학습과 평균 변화만으로 판단해 데이터 품질 문제와 실제 드리프트를 구분하지 못함 | 결측 데이터가 증가하거나 정상적인 분포 변화가 발생하는 경우 | 데이터 품질 검사와 PSI 기반 드리프트 판단을 분리 |

| D7 | ai_ops/policy.js — shouldPromote() | O7 | 적중률이 올랐다는 이유만으로 모델을 승격함 | 평가 표본이 부족하거나 특정 사용자 구간의 성능이 하락한 경우 | 평가 크기, 신뢰구간, 데이터 누수, 구간별 성능 및 지연 시간 확인 |

| D8 | ai_ops/alerts.js — 전체 알림 규칙 | O8 | 알림에 런북, 담당자, 복구 확인 절차가 부족함 | 장애 알림은 발생했지만 담당자와 대응 방법이 정해지지 않은 경우 | 런북 ID와 담당자, 대응 및 복구 확인 절차 연결 |

| 영역 | AI 산출물(%) | 우리 산출물(%) | 점수가 오른 이유 |
|---|---|---|---|
| 파이프라인 게이트 | 41% | 100% | 테스트와 빌드만 확인하던 구조에서 비밀 값, 마이그레이션, 테스트 품질, 커버리지, 변이 점수, 취약점, 모델 품질, 스모크 테스트까지 검사하도록 개선 |

| 알림 규칙 | 71% | 100% | 한 분의 값과 고정 임계값에 의존하던 방식에서 지속 시간, 표본 수, 예상 트래픽, SLO 및 결제·추천 비즈니스 지표를 반영하도록 개선 |

| MLOps 정책 | 19% | 100% | 정기 재학습과 단순 평균 비교를 데이터 품질·PSI 드리프트 판단으로 개선하고, 모델 승격에 신뢰구간·평가 크기·누수·구간별 성능·지연 조건을 추가 |

| 점진 배포 | 41% | 100% | 카나리의 절대 오류율만 보던 방식에서 기존 버전과 비교하도록 변경하고, 지속적인 회귀만 롤백하며 정상 배포와 외부 장애를 구분 |

## 4. 팀의 결론
(공개 시나리오 점수가 높다는 것은 무엇을 보장하고 무엇을 보장하지 않는가?)

공개 시나리오 점수가 높다는 것은 정해진 테스트 환경에서 AI가 기대한 동작을 수행한다는 것을 의미하지만, 실제 운영 환경에서 발생할 수 있는 모든 예외 상황과 데이터 이상, 보안 취약점 및 장애 대응 능력까지 보장하지는 않는다. 따라서 공개 평가 점수만으로 출시를 결정하지 않고, 자체 평가와 런북 검증, 안전장치 및 사람의 승인 절차를 확인한 후 운영 적용 여부를 결정한다.
