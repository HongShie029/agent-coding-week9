### [Mission 2] 작업 단위

- 도구 · 용도:
  - ChatGPT: 작업 계획 수립, 알림 규칙 설계 및 코드 작성 지원
  - VS Code: `monitoring/alerts.js`, `ops/runbook.json`, `docs/OPS_DESIGN.md` 수정
  - 터미널: `npm.cmd run runbook`, `npm.cmd run eval:alerts` 실행 및 결과 검증

- 요청 요약(목표 / 맥락 / 제약 / 검증):
  - 목표: 서비스 운영 지표를 기반으로 이상 상황을 감지하고, 각 알림에 적절한 대응 런북을 연결한다.
  - 맥락: MiniMall 운영 자동화 실습의 Mission 2 수행
  - 제약: 기존 프로젝트 구조와 운영 계약의 기준을 따르고, 담당하지 않은 다른 미션의 파일은 수정하지 않는다.
  - 검증: 런북 연결 및 알림 평가 명령으로 정상 동작 여부를 확인한다.

- 사람이 바꾼 것(계획 · 목록에서):
  - 알림 규칙을 총 6개로 구성했다.
    1. `error-rate-fast`
    2. `latency-creep`
    3. `traffic-drop`
    4. `payment-failure`
    5. `recommendation-quality`
    6. `error-rate-slow`
  - 각 알림에 대응하는 런북을 연결했다.
  - `docs/OPS_DESIGN.md`의 2절에 설계 내용을 정리했다.
  - 구현 후 평가 명령을 실행해 결과를 확인했다.

- 결과(점수 변화):
  - 런북 평가: 100% (6/6)
  - 알림 평가: 100% (10/10)
  - 공개 시나리오 A1~A5 모두 통과했다.
  - 최종적으로 Mission 2 검증을 완료했다.

- 에이전트의 실수 · 미끼에 속은 부분:
  - 확인된 평가 결과에서 에이전트가 미끼에 속거나 별도의 실수를 한 사례는 기록되어 있지 않다.
  - 최종 코드는 평가 시나리오를 모두 통과했다.

- 사람이 확인한 범위:
  - 알림 규칙 6개가 구성되어 있는지 확인했다.
  - 알림과 런북이 연결되어 있는지 확인했다.
  - `npm.cmd run runbook` 실행 결과 6/6 통과를 확인했다.
  - `npm.cmd run eval:alerts` 실행 결과 10/10 통과를 확인했다.
  - 공개 시나리오 A1~A5의 통과 여부를 확인했다.

- 다음에 바꿀 규칙(AGENTS.md):
  - 알림 규칙을 작성하기 전에 운영 계약과 SLO 기준을 먼저 확인한다.
  - 알림별 감지 조건과 대응 런북의 연결을 함께 검토한다.
  - 구현 후에는 런북 평가와 알림 평가를 모두 실행한다.
  - 평가 점수뿐 아니라 개별 시나리오의 통과 여부도 확인한다.
  - 담당하지 않은 다른 미션의 파일은 수정하지 않는다.

### [Mission 4] 작업 단위

- 도구 · 용도:
  - ChatGPT: 점진 배포 및 자동 롤백 로직 설계와 코드 작성 지원
  - VS Code: `deploy/rollout.js`, `docs/OPS_DESIGN.md` 수정
  - 터미널: `npm.cmd run eval:rollout` 실행 및 평가 결과 확인

- 요청 요약(목표 / 맥락 / 제약 / 검증):
  - 목표: 신버전을 단계적으로 배포하고, 오류나 성능 저하가 발생하면 자동으로 롤백하는 시스템을 구현한다.
  - 맥락: MiniMall 운영 자동화 실습의 Mission 4 수행
  - 제약: 운영 계약의 기준을 따르며, 실제 서비스가 아닌 시뮬레이터에서 검증한다. 담당하지 않은 다른 미션의 파일은 수정하지 않는다.
  - 검증: 정상 배포, 오류 급증, 지연 시간 증가, 일시적인 카나리 오류, 외부 장애 등 5개 공개 시나리오를 평가한다.

- 사람이 바꾼 것(계획 · 목록에서):
  - 배포 단계를 5% → 25% → 50% → 100%로 구성했다.
  - 카나리와 기존 버전의 지표를 비교하도록 수정했다.
  - 오류율과 지연 시간의 이상 상태가 3분 연속 지속될 때 롤백하도록 구성했다.
  - 최소 관찰 시간 15분과 단계별 최대 대기 시간 30분을 적용했다.
  - 결제 실패율과 추천 클릭률도 감지 기준에 포함했다.
  - 기존 버전과 카나리 양쪽에 문제가 발생한 외부 장애는 배포 문제와 구분하도록 수정했다.
  - `docs/OPS_DESIGN.md` 3절에 최종 설계 내용을 정리했다.

- 결과(점수 변화):
  - 최초 평가: 41% (4.08/10점)
  - 중간 수정 후 평가: 41% (4.08/10점)
  - 최종 평가: 100% (10/10점)
  - 정상 릴리스 R1, 일시적 카나리 오류 R4, 외부 장애 R5는 정상적으로 완료했다.
  - 오류 급증 R2와 지연 시간 악화 R3는 각각 3분 만에 롤백했다.
  - 최종 공개 시나리오 5개 모두 통과했다.

- 에이전트의 실수 · 미끼에 속은 부분:
  - 초기 로직에서 카나리의 오류 상황과 기존 버전의 상태를 충분히 비교하지 못했다.
  - 일시적인 카나리 오류에도 잘못 롤백하는 문제가 발생했다.
  - 기존 버전에도 문제가 발생한 외부 장애를 배포 문제로 오인해 롤백하는 문제가 있었다.
  - 성능 저하 상황에서 적절한 롤백 판단을 하지 못하는 부분도 수정했다.

- 사람이 확인한 범위:
  - 배포 단계가 5% → 25% → 50% → 100% 순서로 진행되는지 확인했다.
  - 정상 릴리스가 100%까지 완료되는지 확인했다.
  - 오류 급증과 지연 시간 악화 시 자동 롤백되는지 확인했다.
  - 일시적인 카나리 오류와 외부 장애 상황에서 불필요한 롤백이 발생하지 않는지 확인했다.
  - 최종 `npm.cmd run eval:rollout` 결과 10/10점과 공개 시나리오 5개 통과를 확인했다.

- 다음에 바꿀 규칙(AGENTS.md):
  - 카나리 지표만 보지 말고 기존 버전의 지표와 함께 비교한다.
  - 일시적인 오류와 지속적인 장애를 구분하고 연속 관측 조건을 적용한다.
  - 배포로 인한 장애와 외부 장애를 구분한다.
  - 정상 배포, 롤백, 일시적 오류, 외부 장애 시나리오를 모두 검증한다.
  - 평가 점수뿐 아니라 각 시나리오의 결과와 롤백 시점도 확인한다.

- 재시도 횟수: 2회
