## 3. 우리 산출물이 숨은 시나리오에서 틀릴 수 있는 곳 (한계 3가지)
1. **지연 증가 알림의 여유 부족**: 공개 시나리오에서 25분 만에 감지로 기준(25분)과 같다. 지연이 더 서서히 늘거나 평소 지연이 높은 시간대에는 감지가 늦어질 수 있고, 반대로 임계값(SLO 의 90%)이 평소 값에 가까운 시간대에는 오탐이 날 수 있다.
2. **오류 없는 조용한 장애의 감지 지연**: 추천 품질 규칙은 최근 30분을 합산해 평소 클릭률의 70% 미만일 때 티켓을 발행한다. 합산 창이 길어 장애 시작 후 감지까지 시간이 걸리고, 노출 표본이 1,000건 미만인 시간대에는 판단하지 않아 놓칠 수 있다.
3. **공개 시나리오 유형에 맞춘 튜닝**: 임계값과 규칙을 공개 시나리오 유형으로 확인했기 때문에, 숨은 시나리오의 다른 시각 · 크기 · 조합(예: 새벽 저트래픽, 여러 문제가 동시에 발생)에서는 경계 구간의 오탐 · 미탐이 생길 수 있다.

## 4. 사람이 끝까지 책임져야 하는 판단
- **롤백 · 승격의 최종 승인**: 자동 판단은 보조일 뿐이다. 롤백 때 이미 처리된 결제나 데이터베이스 변경은 코드가 되돌려 주지 않으므로 사람이 영향 범위를 확인해야 한다.
- **장애 원인의 검증**: AI 가 말한 근거 로그 ID 를 사람이 직접 열어 존재 · 원인 여부 · 시각을 확인한다. 같은 시각에 있던 무관한 로그(미끼)와 외부 요인을 구분하는 일도 사람의 몫이다.
- **데이터 품질 문제의 조치 결정**: 입력 데이터가 망가진 경우 재학습하지 않고 상류 데이터를 고치게 하는 결정과 그 요청은 사람이 한다.
- **ops-ci 기준값의 결정과 조정**: 기준을 어디에 둘지는 위험과 팀의 부담 사이의 선택이므로 사람이 근거를 갖고 정하고, 운영하면서 다시 조정한다.
